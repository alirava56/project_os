صفحه‌ها از دادهٔ پروژهٔ مجاز استفاده می‌کنند. Viewer و Editor تنها ردیف حساب خودشان را در فهرست اعضا دریافت می‌کنند. نمای `public.projectos_records` شناسهٔ Project، پیوندهای منابع، Parent، وابستگی وظیفه و ارجاع هزینه را قبل از بازگرداندن داده به حساب وب پالایش می‌کند. روابط پنهان قدیمی هنگام ویرایش Task حفظ می‌شوند. تغییر ساختار Resource در اختیار Owner است. مقدار Vault در قرارداد داده وجود ندارد.

هر حساب یک عضویت فعال دارد. دعوت فعلی می‌تواند مجوز کل Workspace یا فهرست پروژه بدهد. رابط دعوت، انتخاب صریح پروژه را پیش‌فرض می‌گیرد. Snapshot نوشتنی برای سازگاری لوکال است و وقتی MFA اجباری است بسته می‌شود. Related record permissions also apply to document histories, monitoring observations and assistant retrieval. [قرارداد API](../architecture/API-CONTRACT.md)

## مرز دسترسی PostgreSQL

| دسترسی | کنترل PostgreSQL |
|---|---|
| هویت و ورود | RLS به‌همراه مجوز ستونی. تابع Login فقط برای ایمیل امضاشده Hash و Salt برمی‌گرداند. |
| نشست و MFA | Digest نشست و کد بازیابی از حساب وب قابل SELECT نیستند. تابع فهرست نشست شناسهٔ مشتق‌شده و زمان‌ها را می‌دهد. محتوای MFA فقط از تابع محدود به کاربر و عملیات MFA خوانده می‌شود. |
| عضویت و دعوت | کاربرد Grant امضاشده به نقش و پروژه‌های فعلی عضویت وابسته است. فقط Owner می‌تواند Grant یک عضو غیرمالک را تغییر دهد یا عضویت او را بردارد. حذف عضویت به‌صورت تراکنشی نشست‌ها را حذف می‌کند. |
| Workerها | Scheduler، HTTPS و Delivery هر کدام حساب محدود به Workspace دارند. شروع با نقش مالک یا خارج از Workspace مقرر خطا می‌دهد. Webhook فقط تحویل را ثبت و وضعیت مخزن تعیین‌شده را pending می‌کند. |
| حساب مهاجرت | حساب جدا برای DDL و عملیات مالک. سه رجیستری خصوصی دارای FORCE RLS و سیاست مالک هستند. اجرای FORCE روی جدول‌های دادهٔ عمومی به کارکرد pg_dump با مالک معمولی وابسته است و فعلاً دسترسی حساب عملیاتی از طریق نقش جدا و RLS محدود می‌شود. |
