# راه‌اندازی و نگهداری سرویس‌های Gate D

مهاجرت‌های PostgreSQL با `npm run db:migrate` و نقش نصب اجرا می‌شوند. برنامهٔ وب و هر Worker ورود مستقل با حداقل مجوز دارند. اطلاعات اتصال و توکن‌ها را به‌صورت متغیر محیطیِ همان فرایند تنظیم کنید. پارامترهای نمونه در این راهنما برای محیط آزمایشی‌اند.

## مدل داده و محدودهٔ دسترسی

| مهاجرت | داده | دسترسی |
| --- | --- | --- |
| 023 | صف GitHub، شمارهٔ نسل درخواست، مرحله و صفحه، Lease و Snapshot آخر | Worker فقط از توابع Claim و Settle برای مخزن ثبت‌شده استفاده می‌کند. وب وضعیت را با Grant پروژه می‌خواند. |
| 024 | یک زمان‌بندی برای هر Workspace، موعد، Lease، خطا و زمان آخرین دریافت معتبر | Worker فقط Workspace و پروژه‌های تخصیص‌یافته را به‌روزرسانی می‌کند. مشاهدهٔ نرخ تابع Grant پروژه است. |
| 025 | آخرین مرحلهٔ SLO هر منبع و Incident متصل، به‌علاوهٔ Outbox موجود | نقش پایش فقط Workspace خودش را پردازش می‌کند. اعلان از نقش مستقل Delivery ارسال می‌شود. |
| 026 | زمان دست‌دهی، پاسخ سرویس محلی و تأخیر | عامل با توکن Workspace و فهرست منابع گزارش می‌دهد. خواندن از مسیر هویت امضاشده و سیاست پروژه انجام می‌شود. |
| 027 | بردارهای سند با نسخهٔ رکورد و شناسهٔ مدل | فقط Owner نمایه می‌سازد. خواندن با Grant زنده و نسخهٔ فعلی سند کنترل می‌شود. ویرایش یا حذف سند بردار قبلی را حذف می‌کند. |

## GitHub

برای هر مخزنِ مجاز، فایل `schema/postgres/grant-github-sync.sql` را با متغیرهای `worker_role`، `workspace_id`، `project_id` و `repository` از طریق `psql -X -v ... -f ...` اجرا کنید. همان نگاشت باید در `PROJECTOS_GITHUB_PROJECTS` وب و Worker باشد. هر عضو آرایهٔ JSON شامل `workspaceId`، `projectId` و `repository` است. وب برای تأیید Webhook به `PROJECTOS_GITHUB_WEBHOOK_SECRET` و Worker برای خواندن GitHub به `PROJECTOS_GITHUB_TOKEN` نیاز دارد.

`npm run github:worker` صف را هر ۱۵ ثانیه بررسی می‌کند. گزینهٔ `-- --once` یک نوبت پردازش را اجرا می‌کند. Job پس از درج رویداد یکتا ساخته یا به‌روز می‌شود. Snapshot پس از تکمیل هر دو فهرست Commit و Issue منتشر می‌شود. سقف اسکن ۱۰۰ صفحه برای هر فهرست و سقف Checkpoint حدود ۸۵۰ کیلوبایت است. در صورت خطا، وضعیت Job و Snapshot قبلی از صفحهٔ پروژه قابل مشاهده‌اند.

## نرخ ارز دوره‌ای

`schema/postgres/grant-currency-worker.sql` به `worker_role`، `workspace_id`، `project_ids` به‌شکل آرایهٔ JSON، `interval_seconds` بین ۳۶۰۰ و ۶۰۴۸۰۰ و `enabled` نیاز دارد. برای توقف زمان‌بندی، Grant را با `enabled=false` دوباره اعمال کنید. هنگام اجرای `npm run currency:worker`، نقش اختصاصی، `PROJECTOS_CURRENCY_WORKSPACE`، `PROJECTOS_CURRENCYAPI_ENABLED=enabled` و کلید CurrencyAPI را تنظیم کنید. این Worker هم از `-- --once` پشتیبانی می‌کند.

هر چرخه یک درخواست برای Workspace ارسال می‌کند. نرخ معتبر به‌شکل رشتهٔ Decimal نگهداری می‌شود و فقط به پروژه‌های فعال و مجاز وارد می‌شود. نرخ بیش از ۴۸ ساعت برای چرخهٔ تازه پذیرفته نمی‌شود. شکست یا محدودیت نرخ مقدار معتبر قبلی را حفظ می‌کند و زمان آخرین دریافت موفق در صفحهٔ مالی دیده می‌شود.

## VPN و رخداد SLO

عامل `npm run monitor:agent` نام رابط WireGuard را از `PROJECTOS_AGENT_WIREGUARD_INTERFACE` می‌گیرد. دستور محلی `wg show <interface> latest-handshakes` فقط آخرین زمان دست‌دهی را استخراج می‌کند. در صورت تنظیم، `PROJECTOS_AGENT_VPN_HEALTH_URL` باید یک نشانی `https://127.0.0.1:<port>/health` با TLS معتبر باشد. پاسخ ۲۰۴ شاهد پاسخ‌گویی سرویس محلی است. مرورگر این شاهد را جدا از دست‌دهی و وضعیت تونل نمایش می‌دهد. دست‌دهی بعد از سه دقیقه و مشاهده بعد از ۱۵ دقیقه قدیمی محسوب می‌شود.

Worker موجود `npm run monitors` پس از هر مشاهدهٔ HTTPS، با فعال‌بودن ترجیح هشدار قطعی، چرخهٔ SLO را بررسی می‌کند. پیش‌فرض‌ها برای `PROJECTOS_SLO_MINIMUM`، `PROJECTOS_SLO_CONSECUTIVE`، `PROJECTOS_SLO_RECOVERY` و `PROJECTOS_SLO_TARGET` به‌ترتیب ۶ نمونه، ۳ خطای متوالی، ۳ پاسخ سالم متوالی و ۹۹٫۹ درصد هستند. نمونه‌های ناشناخته از محاسبهٔ نسبت حذف می‌شوند و زنجیرهٔ نمونه‌های متوالی را می‌شکنند. هشدار داخل برنامه بلافاصله در صف ثبت می‌شود. ایمیل و تلگرام فقط برای کانال پیکربندی‌شده در همان Workspace وارد Outbox می‌شوند. ارسال با Worker موجود `npm run notifications:deliver` انجام می‌شود.

## جست‌وجوی معنایی

مدل آزمایشی محلی، [multilingual-e5-base با مجوز MIT](https://huggingface.co/intfloat/multilingual-e5-base) است. از نسخهٔ ثابت `d128750597153bb5987e10b1c3493a34e5a4502a`، فایل‌های `onnx/tokenizer.json` و `onnx/model_qint8_avx512_vnni.onnx` را در پوشه‌ای بیرون از Git قرار دهید. مفسر Python 3.11 یا جدیدتر به `onnxruntime==1.26.0`، `numpy==2.5.5` و `tokenizers==0.22.2` نیاز دارد. سرویس هش فایل‌ها را قبل از بارگیری بررسی می‌کند.

با `python -B scripts/local-embedder.py --model-dir <model-dir> --port 8766` سرویس روی Loopback آغاز می‌شود. `PROJECTOS_SEMANTIC_TOKEN` برای هر دو فرایند لازم است و وب باید با `PROJECTOS_SEMANTIC_ORIGIN=http://127.0.0.1:8766` به همان سرویس وصل شود. مالک پس از انتخاب پروژه نمایه را می‌سازد. جست‌وجو روی حداکثر ۱۵۰ سند نمایه‌شدهٔ اخیر و حداکثر ۲۴ قطعه از هر سند انجام می‌شود و تا سه شاهد با پیوند منبع برمی‌گرداند. ارزیابی کیفیت و حافظه با `python -B scripts/evaluate-semantic.py --model-dir <model-dir>` اجرا می‌شود.

پرسش و سند به سرویس ابری ارسال نمی‌شوند. سرویس محلی خروجی متنی یا تفسیر دستور ندارد. Vault و انواع دیگر رکورد وارد نمایه نمی‌شوند. محتوای سند باید از ابتدا بدون اطلاعات محرمانه ثبت شود. الگوهای شناخته‌شدهٔ اعتبارنامه و متن حذف‌شده توسط پالایش از استخراج بردار کنار گذاشته می‌شوند.
